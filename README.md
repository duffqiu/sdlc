# SDLC 开发环节调度

Qoder 插件 `sdlc-agent-orchestrator`，版本 `0.4.0`。

先根据任务推荐开发环节，再在主会话内展示可交互表格：每行默认选中推荐模型，可用下拉框更换模型、勾选是否执行，最后点击“确认并继续”。预选只是建议，确认前不启动子会话；确认后由主会话统一调度和处理问答，不走固定 pipeline。

## 设计来源

本插件的整体思路来自 Claude 的文章 [The AI-Native SDLC Playbook](https://claude.com/resources/articles/the-ai-native-sdlc-playbook)。文章讨论的是 AI 原生 SDLC 的组织方式：不以固定流水线为中心，而是按任务选择必要能力，让专门 Agent 承担不同职责，由主控负责编排、上下文交接和人机交互，并用可核验的证据与门禁推进交付。

本项目把这一思路工程化为 Qoder 插件：将文章强调的环节化协作、职责分离和证据驱动交付，映射为可勾选的开发环节、独立会话提示词、环节／模型选择卡片、监督回调、单步产物视图、AC/DoD 证据矩阵，以及可选的 AI Harness 优化环节。它不是对原文的逐字复刻；环节划分、提示词、工具调用、权限边界和本地验证均结合 Qoder 的模型目录、会话接口与 MCP App 能力重新设计。方法论来源以原文为准，具体行为以本仓库实现为准。

## 使用

在 Qoder“扩展 → 已安装”确认插件已启用；在聊天输入框输入 `/`，选择本插件 Skill，并说明任务。例如：

- “按开发环节处理订单退款功能，先让我在表格里选择模型，只交付代码，不上线。”
- “只评审这次变更，不改代码；先展示模型选择卡片。”

主会话读取目标的 Qoder 当前模型目录，调用 `open_stage_selector`。卡片显示本次相关环节、推荐理由、已知费用与输入上限；推荐模型已预选并标注“推荐”，不需要再用文字逐项回复。

- 勾选或取消可选环节，下拉更换模型。
- 项目强制环节标注“必需”并锁定取消，仍可换模型或取消整张卡片回主会话调整范围。
- 点击“确认并继续”后，决定保存并交回主会话；点击“取消”不授权执行。
- 全部可选环节关闭时，按钮明确显示“确认不执行任何环节”。
- 需求、契约、设计等需要你决定的澄清统一由主会话使用 Qoder 内置 AskMe 问答面板（当前工具为 AskUserQuestion），提供选项和推荐理由，已有答案不重复问；子会话只回传问题，不直接打断你。
- 环节／模型仍使用本插件的交互表格，不改成重复问答。空答、跳过、取消或超时不代表批准，只暂停依赖答案的任务；AskMe 不可用时会说明限制，不自动改用自建页面或替你选择。
- 主会话每次收到新输入，会先核对所有未完成任务的状态，再处理新内容；连续输入不会让它跳过状态核实、产物展示或待输入问题，也不会用最新任务覆盖旧任务。
- 子会话意外停止后，主会话会先核实实际状态，不会把静默当完成；原会话可继续时会重新发送任务并要求 supervise 回调，恢复后仍按原候选核对证据。原会话无法恢复或宿主不保证恢复后的回调时会说明限制，是否重新派发由你决定，不会静默换会话冒充原任务。
- 结果统一回主会话；每个环节完成后，主会话都会以单步推进视图展示当前环节产物：一条只读时间线标明已完成、当前与待开始环节，主区域给出产物摘要、关键结论、产物位置/版本、AC/DoD 覆盖、风险与下一步，而不是只报一个“已完成”。已完成环节可回看，但下游环节派发前必须已让你看到上游产物关键信息。宿主提供 `open_stage_dashboard` 工具时，主会话必须同时打开本插件的环节产物仪表盘；仪表盘只是补充视图，不能替代 Markdown 摘要。只有工具不可用、调用失败或宿主不渲染 inline HTML 时才回退到仅 Markdown，并说明原因。
- AskMe 与卡片都不隐藏或替代宿主工具权限审批，生产发布仍需单独授权。

## 开发实现内部的任务拆解与并行

开发实现环节在模型选择卡片中仍只有一行，但可对应多个开发子任务会话，统一沿用你选定的开发模型，不让每个子任务重复选择。主会话先复用已有方案的拆解；较复杂且缺少拆解时，让开发会话先只读分析并返回任务列表，小任务不强制拆分。

拆解（新产出或复用已有拆解）在创建第一个实现子会话前，主会话会先向你发一条独立的任务关系图消息，而不是把图只写进交接包或实现说明：节点是子任务与唯一集成节点，箭头是“完成后才能开始”的依赖，按依赖分层标注并行批次（默认上限 5）和共享资源串行约束，已启用的评审／验收画在集成之后。Mermaid 能渲染时用 flowchart，否则用信息等价的纯文本图并说明展示形式；计划修订或返工后重新出图。图只描述计划，不是派发或预算授权。未拆解的小任务会用一句话说明单任务串行的理由。

主会话核对每个子任务的依赖、读写范围、验收条目和验证方法，默认最多同时运行 5 个开发子任务，并服从更严格的用户预算和宿主限制。无依赖、无读写冲突的任务可并行；共享文件或数据库、测试数据等可变资源冲突时串行，或在已有授权下隔离。并发前说明拆解结果、数量和费用影响；新增范围、模型或超出总预算仍需确认。

各子任务通过回调返回主会话，按子任务ID和派发轮次去重；必需任务失败只暂停依赖它的任务，其他独立工作可继续。全部必需子任务就绪后，停止候选的并发写入，指定一个开发会话串行集成并做整体验证，再把同一稳定候选交给已启用的独立评审／验收。

子会话不会递归调度其他会话，主会话也不会以自己的代码修改代替集成。以上由 Skill 规定如何调用宿主会话工具，卡片服务仍只记录环节与模型选择，不是独立任务调度引擎；实际并行会话、冲突处理及集成效果须在项目中验证。

## 子会话运行时继续使用主会话

派发采用 `callbackMode: "supervise"`。主会话取得受理结果后立即结束当前轮次，你可以继续提问或提交独立的新任务，不必等正在执行的子会话结束。

子会话完成或需要你决策时，由 Qoder 宿主回调主会话；主会话依据任务和会话标识恢复对应上下文，再汇总结果、提问或调度已确认的后续环节。每次继续派发后都再次释放主会话，不用阻塞等待或轮询。

新任务、原任务补充和回调分别关联，不互相覆盖；重复／乱序回调不重复启动，已取消或暂停任务不会因迟到回调自动恢复。宿主决定消息排队次序，插件不改输入队列或权限；本规则不保证主会话能同时运行多个模型轮次。

这些是针对宿主回调能力的调度规范，不是插件自建后台任务服务；真实跨轮回调与宿主调度仍需运行时验证。

## 子会话标题

创建子会话时使用 `create_chat_session` 的顶层 `title` 字段，例如 `title = "开发实现：修复用户登录异常"`；`xxx` 为开发环节中文描述，`yyy` 为 8–10 个汉字的任务描述，不加标点、引号或换行。`prompt` 直接从任务交接包开始，不放命名指令，`systemPrompt` 只放完整开发环节提示词。

宿主不提供 `title` 或旧 Peer 会忽略该字段时，插件会报告命名能力限制并暂停派发，不改用 prompt 前缀。实际标题是否显示仍以宿主可观察状态为准。

## 主控规则注入

插件把主控提示词同时打包为 `rules/sdlc-orchestrator.md`，由 Qoder 插件 `rules` 机制在启用后注入会话；这是插件能使用的会话级规则通道，不等同于改写宿主 system prompt。若宿主未注入该规则，主会话仍需先读取 Skill 中的 `references/sdlc-orchestrator.md` 再执行。

## 组件与前提

- 一个调度 Skill、主控提示词与六份按需加载的环节提示词（含可选的 AI Harness 优化）、会话接口与卡片使用规范。
- 一个无第三方运行依赖的 Node.js stdio MCP Server，由 `.mcp.json` 声明，Node.js 需为 22 或更高版本且宿主能找到 `node`。
- 一张自包含 HTML/JavaScript inline MCP App 卡片，不请求 CDN、外部模型 API 或网络存储，不读取私人模型配置。
- 无全局入口、侧栏入口、Hooks、注册 Agent 或外部模型连接。

卡片服务仅保存选择，不做需求实现、模型推理或会话创建。主控仍在当前主会话；其他环节由宿主独立会话接口创建。

## 确认与安全边界

`open_stage_selector` 只生成待确认草稿，`get_stage_selection` 只读取记录；确认工具 `confirm_stage_selection` 仅对 App 可见。工具可见性由 Qoder 宿主执行，stdio 本身不提供额外调用者身份认证。

卡片确认后经 `ui/message` 回到当前主会话；主会话读取实际选择记录，核对任务与草稿ID，再刷新目标模型目录和检查契约／权限。模型已失效或关键费用／能力变化时重新展示卡片，不自动替换。同一确认记录不能导致重复派发。

选择记录仅存在本插件 Server 进程内，最多100份，一小时后过期。服务重启或记录丢失后需要重新确认，不从聊天文本恢复批准。旧卡片重新打开会读取状态，不自动提交。

操作结果不明时卡片锁定并提示检查主会话；“刷新选择状态”只读取记录，不自动重发确认或消息。已保存但消息未送达时，可在主会话要求读取该草稿继续处理。

Qoder MCP Apps 目前在本地会话提供消息回传能力；Managed SSH／Peer 页面可能仅能展示，缺少能力时隐藏确认／取消按钮，不伪称可执行。目录为空、插件工具不可用或消息能力缺失时由主会话说明条件，不伪造可用列表。

宿主 systemPrompt 覆盖接口不支持云端执行，旧 Peer 也可能忽略覆盖字段；无法核实支持时停止相关派发。需求确认、自测通过、独立验收通过和生产发布授权不能互相替代。

## 本地验证

```sh
npm test
npm run check
npm run preview
```

`npm test` 使用 Node 内置测试框架验证输入、推荐预选、状态、App-only声明、stdio协议与页面消息边界，无需安装 Node 依赖。`npm run preview` 在 `127.0.0.1:47832` 启动仅含测试模型的模拟宿主，不连接或创建真实 Qoder 会话；Ctrl+C 结束。预览不会随插件安装自动启动。

`tests/browser.py` 需要已有的 Python Playwright 和 Chromium，以及已启动的预览服务；它验证真实下拉框、勾选、显式确认、取消、未知结果不重发、不可用能力、深浅色、窄宽布局、键盘和错误日志，截图保存在插件源码目录之外。

静态与模拟宿主浏览器验证不代表 Qoder 内端到端通过。安装后还需确认 MCP 服务连接、卡片在主会话实际渲染、确认消息回传与后续任务调度；不会为了验证安装而自动执行开发任务。

## 来源、审核与安装

设计来源见上文《The AI-Native SDLC Playbook》；本仓库的 Agent、Skill 与环节提示词由用户提供的 SDLC 草稿在本会话中按插件形态修订而来。MCP Apps 接线参考 Qoder 随附的 Host Specification 与 minimal-mcp-app 示例，并实现本插件的任务选择状态。未打包用户配置、密钥、真实私人模型目录或旧安装缓存。

安装前按当前源码执行适用安全审核；历史版本的 SAFE 不替代新版本审核。未自行指定开源许可证，扫描器可能给出未声明许可证的信息提示；检查通过不代表绝对安全。

使用 Qoder 本地插件 ZIP 导入或宿主安装器安装经审核的包。ZIP 根含 `.qoder-plugin/plugin.json` 和 `.mcp.json`。插件安装与当前会话是否已加载不同，结果以宿主返回状态为准；从“扩展 → 已安装”管理启用或删除，无需手改配置文件。
