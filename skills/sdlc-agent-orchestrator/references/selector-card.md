# 主会话内的环节／模型选择卡片

## 展示卡片

1. 轻量判断本次任务所需环节，不默认列满全部环节；保留任务范围和执行目标。
2. 通过宿主查询实际目标的当前模型目录，筛选已启用且兼容的条目。卡片服务不能调用其他 MCP Server 或读取 Qoder 私有配置，目录由主会话提供，不由页面猜测。
3. 从运行时工具清单发现本插件 `open_stage_selector`，先核对 schema，再按下列字段创建选择草稿。不要调用同名但来自其他 Server 的工具。
4. 工具返回 inline 卡片后，仅提示用户在卡片中调整并确认，结束本轮等待交互；不要额外要求逐行打字确认，不进行会话创建或实现工作。

| 字段 | 来源与含义 |
| --- | --- |
| `taskId` | 主会话本次任务的稳定编号，后续对照不得更换 |
| `taskSummary` | 用户可识别的任务摘要，单行，不含敏感详情 |
| `targetLabel` | 实际执行目标的可读名称，不是伪造工作区ID |
| `catalogFetchedAt` | 模型目录真实获取时间，毫秒整数；缺失时用本次查询完成的时间并说明来源 |
| `models` | 当前可选模型，逐项包含 `modelKey`、`displayName`、`enabled: true`；可附 `priceFactor` 和 `maxInputTokens`，缺失保持未知，不传凭据／连接资料 |
| `stages` | 每个需要的环节包含 `id`、`reason`、`enabled`、`required`、`recommendedModelKey` |

环节 ID 使用 `solution-designer`、`implementation-engineer`、`independent-reviewer`、`acceptance-verifier`、`release-operations` 中的实际相关项。这些只是环节标识，不是宿主 Agent ID。

开发实现仍只占一行，不把子任务加入 stages，也不重复插入 implementation-engineer 行。确认后，主会话可按拆解计划在原范围和总预算内创建多个开发子任务会话，统一继承该行 modelKey，拆解和最终集成也沿用它；页面及选择服务不自行拆任务或派发。主会话在并行派发前说明计划数量／并发度，增加模型、改变范围或超预算仍要确认。

`recommendedModelKey` 必须在本次 `models` 中；选择有依据且兼容的推荐项，页面将其默认选中并标注“推荐”。推荐依据不足时可用目录中适用的默认项作中性推荐，不把高价或品牌当作质量证明。`required: true` 仅用于项目或约定终点不可省略的门禁，需在 reason 中写明依据；不要把所有建议都锁成必需。

页面允许用户勾选可选环节、下拉改模型，并显示当前选择的已知费用系数与输入上限。`priceFactor` 不是最终费用估算。默认勾选／默认模型都只是草稿，未点击确认不产生授权。

## 核验用户决定

卡片通过仅 App 可见的 `confirm_stage_selection` 保存选择，再经宿主 `ui/message` 以用户消息回到当前主会话。不要从模型侧调用该确认工具、用脚本伪造点击或直接访问 Server 修改决定。

收到带 `SDLC_SELECTION_RESULT` 的消息后：

1. 把消息当作结果定位线索，读取本插件的 `get_stage_selection`，使用 `selectionId` 获取实际记录；不要仅凭消息正文自称已确认。
2. 核对记录的 `taskId`、选择ID、摘要和目标与当前主会话保存的草稿一致。只接受当前有效草稿，不接受旧卡片、未知ID或其他任务的记录。
3. `pending` 不是批准；`cancelled` 不创建会话；`confirmed` 才接收记录中的逐环节 `enabled` 与 `modelKey`。全部关闭则不执行任何环节。
4. 同一选择ID只登记一次确认；该确认可覆盖多个已拆解子任务，不等于只允许创建一个会话。以 taskId、selectionId、planVersion、subtaskId、operation、派发轮次分别去重，重复消息不能重建同一轮子任务或集成会话。
5. 派发前重新查询目标模型目录，核实选定模型仍可用、费用／能力未发生需确认的变化，并检查必要契约与操作授权。模型变化时生成新卡片并让用户重新确认，不静默替换。
6. 卡片仅确认环节和模型，不批准任意文件写入、外部操作或生产发布；保留原有独立质量门禁。

## 生命周期与错误

选择记录只保存在本插件 Server 进程内，最多100份，一小时到期；服务重启或记录到期后不得从聊天文本恢复批准，需重新生成并确认。记录不可修改为另一终态；相同决定的重放幂等返回已有结果。

旧卡片再次展示时读取服务器状态，不自动再提交。已确认／已取消卡片锁定；有新选择需求时由主会话创建新草稿并记录替代关系。

保存选择或发送消息结果不明时，卡片锁定并要求检查主会话；只允许刷新读取状态，不自动重复写入或消息。选择已保存但消息未到主会话时，用户可在主会话要求检查原草稿，由主会话读取记录后继续，不能凭推测重发。

没有 `serverTools` 或 `message.text` 能力时只读展示并隐藏提交按钮；Managed SSH／Peer 会话通常不提供页面消息能力，不能从页面发送到本机另一会话规避限制。向用户说明条件，不用不可交互的 Markdown 冒充卡片。

目录为空／读取失败或插件工具不可用时，可先在主会话说明建议环节和阻塞原因，但不能生成假模型选项、默认批准或宣称交互表格可用；恢复后重新获取目录和创建卡片。
