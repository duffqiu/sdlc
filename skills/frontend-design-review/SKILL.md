# 前端设计审查

对已实现界面做只读、基于证据的视觉与交互审查。发现问题只报告，不修改产品。

## 输入

- 已确认的 `DESIGN.md`、mock 或截图基线；来自 `design-styles/<slug>` 时记录 slug 和上游链接
- 待审查的候选版本、运行方式和环境
- 目标浏览器、设备、视口和必须覆盖的用户流程

## 检查维度

1. 方向一致性：字体、配色、间距、圆角、阴影、动效和背景是否符合已确认方向。
2. 视觉层级：标题、正文、辅助信息、主操作和次操作是否清晰；是否有拥挤、错位或过度装饰。
3. 排版：字号、行高、字重、行长和断行；窄屏是否溢出或截断。
4. 颜色与对比度：文字、边框、状态色和焦点态是否满足可读性。
5. 布局与响应式：窄屏、常规、宽屏；栅格、留白、叠层和固定元素是否稳定。
6. 交互状态：悬停、焦点、按下、禁用、加载、空、错误和成功。
7. 无障碍：键盘路径、焦点可见、语义结构、标签、减少动效和替代文本。
8. 性能与稳定性：明显布局抖动、阻塞动画、图片尺寸和控制台错误。

## 方法

- 使用真实浏览器或设备，不只读代码；截图必须来自实际候选版本。
- 对有争议的视觉判断，给出基线、实际截图和具体差异。
- 每个问题包含编号、严重性、位置、复现步骤、预期/实际和证据。
- 区分已确认缺陷、待验证项和审美建议；主观偏好不阻断交付。
- 不修改代码、样式、设计标准或验收条件；需要修复时交主会话安排实现。

## 输出

返回主会话可直接展示的摘要：

- 状态：PASS / NEEDS_WORK / BLOCKED
- 覆盖的页面、视口和流程
- 阻断问题与非阻断建议
- 截图/日志证据位置
- 未覆盖范围和复测建议

审查 PASS 只代表本次视觉与交互范围，不替代功能验收或发布授权。
